Project overview

Built for the field

SteelDrop Field Services is a custom Salesforce org built to manage the full operational lifecycle of a fitness equipment delivery and installation company — from equipment catalogue and site management to job scheduling, technician dispatch, and billing.

"Designed from real field service operations experience — every object, field, and relationship reflects how commercial fitness equipment delivery actually works, from trade show setups to apartment development deadlines."

The build demonstrates core Salesforce administrator competencies: custom object modelling, junction objects, roll-up summary fields, formula fields, dependent picklists, data import via Data Import Wizard, and operational dashboard creation.

Data model

Object architecture

Seven objects — five custom, two standard — connected through lookup and master-detail relationships to model the complete field service operation. A junction object handles multi-equipment job line items with quantity, unit pricing, and formula totals.

Custom object
Delivery_Job__c
The core operational record. Every job has a site, account, technician count, labour billing, and auto-calculated totals.
Job_Status__c Job_Type__c Priority__c Labour_Total__c Equipment_Total__c Job_Total__c SLA_Breach__c Site__c
Custom object
Equipment__c
Full product catalogue with dependent picklist classification by category and sub-category, weight, assembly time, and condition.
Equipment_Category__c Equipment_SubCategory__c Brand__c Model_Number__c Weight__c Requires_Assembly__c Assembly_Time__c
Junction object
DJ_Equipment__c
Links Delivery Jobs to Equipment records. Handles multi-item jobs with quantity, unit price, and formula-calculated line totals.
Delivery_Job__c Equipment__c Quantity__c Unit_Price__c Total_Price__c Serial_Numbers__c
Custom object
Site__c
Delivery locations with site type classification — residential, gym, corporate, school, retirement home, apartment development, trade show.
Site_Type__c Account__c Access_Notes__c Open_Day_Deadline__c City__c State__c
Custom object
Technician__c
Field staff roster with zone assignment, employment type, and certifications including CDL, Manual Handling, Electrical Safety, and Forklift.
Zone__c Employment_Type__c Certifications__c Active__c Email__c Technician_External_ID__c

Scheduled technician visits tied to a Delivery Job via Master-Detail. Tracks scheduled vs actual times and customer sign-off.

Billing logic

Formula-driven job costing

SteelDrop uses formula fields and roll-up summaries to automate billing calculations across every job — no manual arithmetic, no spreadsheet dependency.

Labour is charged per technician per hour — reflecting how field service operations actually bill. Equipment totals roll up from the junction object line items. The Job Total combines both automatically.

01
Labour Cost Formula
Field: Labour_Total__c on Delivery_Job__c
Dispatcher logs number of technicians and hours on job
Labour Total = Number_of_Technicians__c × Hours_on_Job__c × Labour_Rate__c
Updates instantly on every save — no manual calculation needed
02
Equipment Roll-Up + Job Total
Roll-Up Summary + Formula on Delivery_Job__c
Line items added via Delivery_Job_Equipment__c junction object
Each line: Total_Price__c = Quantity__c × Unit_Price__c
Equipment_Total__c rolls up the SUM of all line item totals
Job_Total__c = Equipment_Total__c + Labour_Total__c

Build process

How it was built

Built in a Salesforce Developer Edition org in a single structured session — designed from real field service operations experience at a commercial fitness equipment delivery company. Every object and field maps to an actual operational requirement.

Phase 1
App and object design
Created the SteelDrop Field Services Lightning app. Built 5 custom objects from scratch — Equipment, Site, Delivery Job, Technician, Service Appointment — plus a junction object for equipment line items.
Phase 2
Field architecture
50+ custom fields including dependent picklists (Equipment Category → Sub-Category), formula fields for labour and job totals, roll-up summary for equipment totals, and external ID field for data import matching.
Phase 3
Relationship mapping
Master-Detail relationships from Service Appointment to Delivery Job and junction object to both parent objects. Lookup relationships from Delivery Job and Site to Account, enabling roll-up summaries and relational reporting.
Phase 4
Data import
93 delivery jobs, 16 technicians, 20 accounts, 10 sites, and 93 service appointments imported via Data Import Wizard using Python-generated CSVs. Multiple import iterations required — all debugged and resolved including External ID matching for Technician lookups.
Phase 5
Reporting and dashboard
Five reports built — Jobs by Status, Jobs by Site Type, SLA Compliance, Revenue by Job, and Technician Utilisation. Five-component operations dashboard pinned to the SteelDrop app home page.
Architectural decisions

Key design notes

Junction object over multi-select picklist
Equipment type was initially considered as a multi-select picklist on the Delivery Job. Rejected in favour of a junction object — enabling quantity tracking, unit pricing, line-item totals, and roll-up summaries that a picklist cannot support.
Labour billed per technician per hour
Based on real Prosource billing practice. The formula field reflects the actual billing model used in commercial fitness equipment delivery — not a flat rate or per-job charge. This makes the data model directly transferable to a real operation.
External ID for Technician lookup import
Salesforce Data Import Wizard cannot match custom object lookups via Salesforce ID. An External ID field (Technician_External_ID__c) was added to the Technician object — enabling reliable CSV-based lookup matching across 93 service appointment records.
